# Review 与收敛记录（2026-11-24）

## 当前结构

- `attach/build.py`：唯一构建入口，直接生成内存 class 补丁与单文件可执行程序。
- `attach/patch_config.py`：验证版本清单，执行固定字节修改，生成运行时几何规则。
- `attach/tools/PatchViews.java`：构建时的 ASM 方法修改器，一次进程处理所有菜单 class。
- `attach/java/`：唯一菜单实现、Agent、事务状态、UI 调度、结果文件与现存控件更新。
- `attach/cmd/daynight-attach/`：唯一 Go 模块／车机入口，负责 Attach、自动 PID 与临时文件。
- `source/2995/inputs.json`：所有 2995 文件摘要、class 摘要、修改点、控件尺寸和模式映射。

删除了不参与 Attach 的部署与构建入口。不会先构建完整替换 JAR 再拆回 class，
也不会在两个语言的构建器里重复编译菜单。Agent 的固件摘要和运行时几何来自清单生成资源。

## 修复与回归覆盖

| 问题 | 处理 |
| --- | --- |
| 回退失败仍可能报告安装成功 | 显式 RECOVERY_REQUIRED 状态；阻止再次 install，支持 remove 恢复 |
| 过期读回仍补发模式请求 | epoch／request 校验及原子点击认领；旧实现已复现该失败 |
| 控件同名或同尺寸时误匹配 | 版本清单固定视图、索引、名称与尺寸；修改前检查完整布局 |
| UI 请求中断后修改仍在后台进行 | 排队请求可取消，开始的任务等待完成并保留中断状态 |
| 先修改后发现报告不可写 | CREATE_NEW 预留结果文件并保持同一描述符 |
| 客户端只检查 ok 字段 | 验证动作、PID、start time 与最终状态 |
| 构建失败留下不完整目录 | 清理本次创建的输出，不覆盖已有构建 |
| 多处维护版本规则 | 文件、字节码与活体控件规则集中到一个版本清单 |
| 完整候选 JAR 的冗余打包 | 只生成目标 class 定义；测试确认工作目录没有候选 JAR |

## 验证方式

自动化测试覆盖 Attach 协议、进程识别、临时文件清理、事务失败、队列取消、中断、
异步过期回调、结果文件、构建边界、版本清单、目标范围和生成的几何规则。
Go 测试启用 race；Java/Agent 输出为 Java 8 class。新构建的十个视图定义与此前已验证实现
逐字节相同，原 JAR 保持不变。

虚拟机用原厂 ARM64 JVM 验证动态加载、三行菜单、AUTO、模拟日夜输入、同外观手动切换、
卸载、再次加载和重复加载，并核对同一 PID／启动时间。日志、截图和输入保留在本机验证目录，
不把构建成功或一条初始化日志当成实际界面成功。

GitHub `master` 推送触发单一 Build patch 流程，版本矩阵读取 `source/<版本>/`。
真实车辆 Attach、硬件灯光、长期稳定性和跨重启保存未验证。

## 回退

同一可执行文件运行 `daynight-patch remove`，无需停止或重启 HMI。原文件没有修改。
恢复失败时先 remove，不重复 install；要换另一构建，先卸载并在独立 JVM 中测试。
